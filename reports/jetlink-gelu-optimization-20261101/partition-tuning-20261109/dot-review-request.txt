已有结果（严格区分测量范围）
1. 旧全 NPU + 顶层共享 I/O：1200 帧，固定重复合成道路图、递归状态反馈、20 Hz，均值 32.475 ms，P99 33.437 ms。只是原生 Run 推理时间，未包含摄像头/传输/应用 staging。后续 5 帧和 16 个 varied 帧数值对照失败；有限输出不等于精度通过。
   原始记录：reports/jetlink-gelu-optimization-20261101/partition-tuning-20261109/legacy-32ms/light-speed-baseline-20261031.md
   旧源码：同一 legacy-32ms/ 目录的 qnn_context_probe.c、qnn_jl_shared.c。
2. 保留两种 GELU 公式的准确修复：36 个 vision erf GELU + 27 个 policy tanh GELU 用 CPU 精确 FP16 查表，成为 45 个 NPU EPContext + 63 个 CPU 节点。后续共享全部中间边界、减少最后 transformer 层多余 query 计算后，160 帧均值 52.4086 ms，160 帧输出与准确 baseline 逐字节一致，原始数值阈值全部通过。
   结果：reports/jetlink-gelu-optimization-20261101/partition-tuning-20261109/last-query-full160/summary.json
   对应模型产物 whole-context-last-query-shared-all.onnx 未上传；请依据已提交的生成脚本、manifest、summary 和 parity 日志审查，勿假定可直接加载该模型。
3. 6-op native GELU projection：16 帧原始阈值通过，但约 63.745 ms；shared-cache 版本约 58.741 ms。简化 3-op Min(Gelu(x),Relu(x))：50.463 ms，五个 head 失败。bounded-LUT 整图约 258.901 ms；不要把它们当作尚未试过的快速修复。
4. NPU 准确 vision + LiteRT GPU policy 混合已跑通、正常退出：160 帧均值 65.284 ms，热身后约 65.027 ms；vision 42.726 ms，bridge 0.177 ms，policy 22.124 ms。160 帧均有限，但原始 checker 在 plan 的两个 quiet 列失败（最大误差约 0.004188/0.003910，门槛 0.003435）。16 帧先前通过。不是一个已通过完整精度的快模型。
   结果：reports/jetlink-gelu-optimization-20261101/partition-tuning-20261109/mixed-litert-160-confirm/
5. 用户曾观察官方 GPU 约 40 ms，未完成同条件复现或精度验证，不宜作为已验证准确基线。独立完整 LiteRT GPU 原图曾有 NaN；通过 LayerNorm epsilon 等价变换消除所测 16 帧非有限值，但约 81 ms。QNN GPU FP32 policy 在 OpenCL kernel binary 初始化时崩溃，关闭 MatMulAddFusion 仍未解决。

关键因果证据和不能外推的范围
- reports/jetlink-precision-audit-20261101/README.md：NPU vision + CPU32 policy 仍失败 lane_lines/road_edges；CPU vision + NPU policy 也有独立失败。不能把全 NPU 失败全部归到某一支路。
- reports/jetlink-operator-audit-20261101/README.md：同一真实 block 输入的单节点 audit，GELU 的局部 HTP 误差明显高于 sampled LayerNorm/MatMul，出现正输入时 GELU 输出超过输入。只覆盖单节点/单激活，不能绝对排除其它层累计误差。
- reports/jetlink-gelu-repair-20261101/README.md：仅修 36 个 vision GELU 后仍有三个 head 失败；其 vision 特征送入独立 FP32 policy 后通过，扩大为两种公式的修复才通过全部检查。
- ORT QNN GELU builder 映射到 QNN_OP_GELU，已审查路径未转发 ONNX approximate 属性；原模型的 erf 与 tanh 两种公式不能随意互换。
- CPU GELU 已经是有限 FP16 位模式查表，并非逐元素 erff；循环展开、线程数、affinity、spinning、shared I/O 等都有既有记录，勿重复当作新提速。
- 尚无证据证明必须修全部 63 个节点，也没有更小修复子集通过整图的既有结果；应区分“未证明不可能”和“有理由值得投入”。
- reports/jetlink-gelu-optimization-20261101/sdk/README.md：HTP 自定义算子工具链研究。没有完成匹配 QNN 2.42 / v73 的算子构建；HVX vlut16 不代表可以一次高效 gather 整个 128 KiB FP16 LUT。不要将可编译或 ISA 理论能力当作实际性能。
